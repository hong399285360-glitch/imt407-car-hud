启动日期: 2026-09-05 · 跟踪日志: PROGRESS.md

3.3 电源方案

汽车电源环境恶劣（瞬时高压、浪涌、抛负载）。F407 板子直接接点烟器会烧。
  • 车充 USB 5V/2A → 给平板充电 + F407 供电（F407 板载 5V→3.3V LDO）
  • AMS1117-3.3 独立给 ESP8266 供电（5V→3.3V，峰值 300mA）
  • TVS 二极管（SMBJ24A）跨在 5V 输入端防浪涌
  • 所有模块共地

五、代码骨架

5.1 ESP8266 AT 命令初始化

// wifi.c - ESP8266 初始化为 AP + TCP 服务器
void ESP8266_Init(void) {
    // 1. 复位
    ESP_Send("AT+RST\r\n");
    ESP_WaitOK(2000);

    // 2. 设为 AP 模式（平板直连，不需要路由器）
    ESP_Send("AT+CWMODE=2\r\n");
    ESP_WaitOK(1000);

    // 3. 配置热点
    ESP_Send("AT+CWSAP=\"F407-HUD\",\"12345678\",5,3\r\n");
    //              SSID        密码     通道  WPA2
    ESP_WaitOK(2000);

    // 4. 启动 TCP 服务器，端口 80
    ESP_Send("AT+CIPMUX=1\r\n");      // 多连接模式
    ESP_WaitOK(500);
    ESP_Send("AT+CIPSERVER=1,80\r\n"); // 开TCP服务
    ESP_WaitOK(1000);
}

// 向指定连接ID发送数据
void ESP_SendJSON(uint8_t conn_id, char* json, uint16_t len) {
    char cmd[32];
    sprintf(cmd, "AT+CIPSEND=%d,%d\r\n", conn_id, len);
    ESP_Send(cmd);
    HAL_Delay(50);
    ESP_SendRaw(json, len);  // 发JSON体
}

5.2 OBD 读取（ELM327 AT 命令）

// obd.c - ELM327 通信
void OBD_Init(void) {
    OBD_Send("ATZ\r");       // 复位
    HAL_Delay(500);
    OBD_Send("ATE0\r");      // 关回显
    OBD_Wait("OK");
    OBD_Send("ATSP0\r");     // 自动协议
    OBD_Wait("OK");
    OBD_Send("0100\r");      // 协议探测
    HAL_Delay(1000);
}

// 读 PID，返回原始响应字符串
int OBD_ReadPID(uint8_t pid, uint8_t* data) {
    char cmd[16];
    sprintf(cmd, "01%02X\r", pid);
    OBD_Send(cmd);
    // 响应格式: "41 XX DD DD..." 解析DD
    // 例: 010C(转速) → 41 0C 1A F8 → (0x1AF8)/4 = 1726 RPM
    return OBD_ParseResponse(pid, data);
}

// 常用 PID
// 0C = 转速, 0D = 车速, 05 = 水温, 11 = 油门, 42 = 控制模块电压
// EV专用: 5B = SOC, 5C = 电池温度 (ISO 15031-5 扩展)

5.3 能耗算法

// energy.c - 功率积分计算 kWh/100km
typedef struct {
    float power_kw;      // 瞬时功率 (电压×电流/1000)
    float energy_kwh;   // 累计消耗能量
    float regen_kwh;    // 累计回收能量
    float distance_km;  // 累计里程
    float energy_per_km; // kWh/100km 滑动窗口
} EnergyState;

// 每100ms调用一次, 用FPU做浮点积分
void Energy_Update(EnergyState* s, float voltage, float current, float speed_kmh) {
    s->power_kw = voltage * current / 1000.0f;
    float dt = 0.1f;  // 100ms
    float dE = s->power_kw * dt / 3600.0f;  // kWh
    if (s->power_kw > 0) s->energy_kwh += dE;
    else s->regen_kwh += -dE;
    s->distance_km += speed_kmh * dt / 3600.0f;
    if (s->distance_km > 0.01f)
        s->energy_per_km = (s->energy_kwh - s->regen_kwh) / s->distance_km * 100.0f;
}

七、避坑指南

7.1 F407 通用避坑

  • DMA缓冲区不要放CCM：F407 的 64KB CCM 对 DMA 不可见，放进去数据搬不动
  • I/O严禁接5V：F407 I/O 是 3.3V，虽然多数5V容忍但不能当5V驱动
  • 串口下载禁用FlyMcu：会锁F407芯片，用STM32CubeProgrammer
  • GPIO驱动能力：单脚±25mA极限，总电流≤150mA
  • 3.3V排针别接5V：认准丝印，接错烧主控

7.2 ESP8266 避坑

  • 峰值电流300mA：F407板载LDO可能不够，建议独立AMS1117-3.3供电
  • EN/CH_PD必须拉高：不拉高模块不启动
  • 3.3V电平：ESP8266 RX 不耐5V，F407 TX(PA9)是3.3V正好匹配
  • AT固件版本：刷标准AT固件（非NodeMCU/Lua），支持CIPSERVER命令

7.3 OBD 通信避坑

  • 极狐T1的OBD PID：标准PID(010C转速等)通用，但SOC/电池温度可能用扩展PID(015B/015C)或ISO 15118，需实测
  • ELM327响应延迟：蓝牙版3-8Hz，UART版15-30Hz，直连CAN 100+Hz
  • 不能同时插两个OBD设备：用一转二延长线共用
  • 只读不写：GB44495法规限制，不要尝试写入/刷写

7.4 HUD 投影避坑

  • 屏幕亮度300-400nit：白天阳光直射偏暗，夜间/阴天够用
  • 必须镜像翻转：HTML5用 transform: scaleX(-1)，否则反射后左右颠倒
  • 纯黑底+高饱和色：黑色不反射减少眩光，黄/绿/白色字最亮
  • 反射膜选专用HUD膜：普通玻璃反射率~8%，专用膜30-40%

九、安全红线

  • 只读OBD标准PID：不注入CAN报文，不刷写ECU，不修改车辆参数
  • 不碰高压系统：极狐T1 400V平台，高压线束黄色标识，绝不拆碰
  • HUD不分散注意力：内容极简（速度/电量/导航），驾驶时余光瞥一眼即可
  • 电源隔离：车充取电加TVS，不用车载12V直供F407
  • 接线检查：通电前用万用表确认VCC/GND不短路、电平匹配
  • 行车安全：调试在停车状态下进行，行驶中不看HUD调试数据

十、备选进阶方向

  • 电池SOH长期追踪：SD卡记录每次充放电曲线，月度对比容量衰减
  • 驾驶行为AI评分：IMU+OBD数据→TinyML模型(50KB)→急刹/急转/疲劳检测
  • 振动异响诊断：麦克风(I2S)+FFT频谱分析，悬挂/轴承异常预警
  • F407双CAN直读：绕过ELM327，直读CAN总线(100+Hz)，需确认网关过滤范围
  • 多屏仪表：FSMC驱动并口大屏+SPI副屏，三屏并发(DMA+双缓冲)
